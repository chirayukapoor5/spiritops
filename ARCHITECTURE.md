# SpiritOps contracts

A single trusted local host runs one API process, one worker, SQLite-backed MLflow and Streamlit. SPIRITOPS_HOME (default .spiritops) is a shared directory. MLFLOW_TRACKING_URI is configurable. SQLite WAL coordinates API, worker and CLI. The deployment manifest is a transactional SQLite singleton, updated together with its audit event. Artifacts are immutable native LightGBM text or JSON. No pickle loaders. One request pins one loaded version. Use Monday ISO dates and litres. One-step-ahead forecasts only. Never fit on the evaluation window or backdate production forecasts.

## Data and model interfaces (Python 3.11)
- spiritops.ingestion.ingest(home: Path, mode: str = "demo") -> dict. Publish immutable weekly Parquet and atomically replace home/data/current.json containing path (relative to home), sha256, first_week, last_week, products (list of strings), product_selection_end. All dates ISO. Rows include product (str), week, volume, category, price. Zero-fill complete weeks. Reports include quarantine and provenance.
- spiritops.features.SCHEMA_VERSION; features_for(home, product, week: str) -> dict[str,float]. Numerical finite features; raise ValueError outside supported horizon/unknown products. Include lag1 and seasonal_naive numeric keys. Cache by immutable snapshot.
- spiritops.training.fit(home, out: Path, validation_start: str, validation_end: str, kind: str="lightgbm") -> dict (training metadata, dataset and profile). kind also supports "baseline". Write out/model.json with schema_version and needed parameters, and optional model.txt. spiritops.training.load(out) -> predictor with predict(rows: list[dict[str,float]]) -> list[float]. spiritops.evaluation.evaluate(home, candidate, incumbent, start, end) -> dict with passed:bool, reasons:list[str], candidate:{wape,mae,bias}, incumbent:{...}, latency_ms, and evaluation bounds. incumbent=None compares against seasonal naive. A baseline bootstrap is allowed only with integrity, finite and latency gates. Independent evaluation weeks must follow both training cutoffs; challengers need >=2% relative WAPE gain.
- spiritops.worker.enqueue(home, key: str, payload: dict) -> str ; job(home,id)->dict|None ; run_once(home)->bool ; python -m spiritops.worker loops and calls spiritops.monitoring.tick(home) periodically. Payload includes kind, validation_start, validation_end. If omitted, use final eight complete weeks. Retry/recover boundedly. Enqueue after ingestion only.
- spiritops.deployment.current(home)->dict (version as string, validation_end etc); spiritops.deployment.predict(home, rows)->tuple[str,list[float]]; history(home)->list[dict]; rollback(home,reason)->dict. No active version raises RuntimeError. History includes reasons/outcomes. Worker writes MLflow candidate and gates activation, tracks aliases.
- API/monitoring own home/observations.sqlite3, all their own tables. Worker/deployment own home/control.sqlite3. API adds GET /v1/products (current.json), GET /v1/jobs and GET /v1/observations, GET /v1/operations. POST /v1/predict {product,week}, response {product,week,version,prediction, prediction_id}. Batch {items:[...]}. POST /v1/feedback {product,week,actual}. POST /v1/admin/retrain optional JSON job parameters; X-Admin-Token from SPIRITOPS_ADMIN_TOKEN. Dashboard uses HTTP only.
- Commands: spiritops data [--mode demo|full], spiritops train, spiritops demo, spiritops benchmark, uvicorn spiritops.api:app, python -m spiritops.worker, streamlit run dashboard/app.py.
