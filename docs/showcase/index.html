SpiritOps

Weekly wholesale purchase forecasts with automatic retraining, model evaluation and rollback.

Static showcase · Recorded on a local CPU-only deployment

Model lifecycle

The recording shows stored decisions from a statewide historical replay. The controlled run lowered the alert threshold. A 28.22% WAPE development candidate was promoted. The holiday challenger was rejected and 200 shadow forecasts were recorded before their labels arrived. The default-policy replay queued no job because its reserved holdout extended beyond the available data.

Single-host architecture

Iowa invoices → DuckDB validation → weekly Parquet → shared features
Worker → LightGBM → MLflow → release gates → deployment manifest
FastAPI → predictions + matured labels → monitoring → worker queue

Measured service behavior

All 64 requests during controlled retraining and activation succeeded. Injecting a missing artifact restored the previous version in 2.26 seconds. Under eight concurrent clients, the median run P95 for repeat requests fell from 303 to 142 ms. First-time writes for different products still reached 307 ms P95.
